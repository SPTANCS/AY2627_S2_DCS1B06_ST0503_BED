Refactoring an Express App: Routes, Controllers, Utils & Middleware

Take a mosquito detection server for HDB estates that lives entirely inside one index.js file and refactor it into a clean, layered src/ structure. You will start from a working-but-messy server, split it into routes and controllers, pull repeated logic into utils, and finish by writing reusable middleware.

✦ Code-along
Step 1 of 9
01
Where We Are Starting
A working mosquito detection server, with every single responsibility crammed into one file.

You have been handed a small server for HDB mosquito detection. Field officers submit reports of mosquito larvae found at HDB blocks, and the server stores them in memory.

The problem is where that code lives. The entire application, meaning the data, the routing, the request handling, and the validation, sits inside a single index.js.

There are two in-memory arrays: blocks (the HDB blocks being monitored) and reports (each mosquito detection report filed against a block).

index.js
javascript
import express from 'express';

const app = express();
app.use(express.json());

// --- In-memory data ---
const blocks = [
  { id: 1, blockNumber: '123A', town: 'Tampines', postalCode: '521123' },
  { id: 2, blockNumber: '456B', town: 'Yishun', postalCode: '760456' }
];

const reports = [
  { id: 1, blockId: 1, larvaeCount: 12, reportedAt: '2026-08-01', status: 'open' },
  { id: 2, blockId: 2, larvaeCount: 3, reportedAt: '2026-08-05', status: 'closed' }
];

// --- Report endpoints ---
app.get('/api/reports', (req, res) => {
  res.status(200).json(reports);
});

app.get('/api/reports/:id', (req, res) => {
  const report = reports.find((r) => r.id === Number(req.params.id));
  if (!report) {
    return res.status(404).json({ message: 'Report not found' });
  }
  res.status(200).json(report);
});

app.post('/api/reports', (req, res) => {
  const { blockId, larvaeCount } = req.body;
  if (!blockId || larvaeCount === undefined) {
    return res.status(400).json({ message: 'blockId and larvaeCount are required' });
  }
  const newReport = {
    id: reports.length + 1,
    blockId,
    larvaeCount,
    reportedAt: new Date().toISOString().slice(0, 10),
    status: 'open'
  };
  reports.push(newReport);
  res.status(201).json(newReport);
});

// --- Block endpoints ---
app.get('/api/blocks', (req, res) => {
  res.status(200).json(blocks);
});

app.get('/api/blocks/:id', (req, res) => {
  const block = blocks.find((b) => b.id === Number(req.params.id));
  if (!block) {
    return res.status(404).json({ message: 'Block not found' });
  }
  res.status(200).json(block);
});

app.listen(3000, () => {
  console.log('Mosquito server running on port 3000');
});

This file works, but notice the problems that grow with every new feature:

• The URL paths and the request-handling logic are tangled together, so you cannot see the API surface at a glance.
• The find(...) lookup by id will be copy-pasted for every resource.
• There is nowhere to put logic that is shared between endpoints (logging, validation, risk scoring).
• Adding blocks, inspectors, and fogging schedules would push this past 500 lines.

💡

The refactor you are about to do changes zero behaviour. Every endpoint must respond exactly as it does now. That is what makes it a refactor rather than a rewrite, and it is why you should test after every step.

2

Planning the src/ Structure
Decide where every piece of code will live before you move a single line.

The target structure separates the app into layers. This is what your project will look like by the end of the lesson:

project structure (target)
bash
mosquito-server/
├── index.js                    # app setup + mounting routes only
├── package.json
└── src/
    ├── data/
    │   └── store.js            # the in-memory arrays
    ├── routes/
    │   ├── reportRoute.js      # WHICH url maps to WHICH handler
    │   └── blockRoute.js
    ├── controllers/
    │   ├── reportController.js # WHAT happens for each request
    │   └── blockController.js
    ├── utils/
    │   ├── collectionUtils.js  # small reusable helpers
    │   └── riskUtils.js
    └── middleware/
        ├── requestLogger.js    # runs BEFORE handlers
        ├── validateReport.js
        └── notFound.js

The mental model for each layer:

• Route is the address book. It only says "GET / goes to getAllReports".
• Controller is the worker. It reads req, decides on a result, and calls res.status(...).json(...).
• Utils are pure helper functions. No req, no res, just input in and output out.
• Middleware is code that runs on the way into a handler, and either passes control on with next() or ends the request.

Both controllers will need the arrays, so they must live in a module that anyone can import.

Step 5 of 9
05
Create the Route File and Mount It
A router is a mini-app. It owns the paths, and index.js decides where those paths hang.

The matching route file is src/routes/reportRoute.js. It imports Router from Express, registers each path against a controller function, and exports the router at the bottom as the file's default export.

A route file holds no logic of its own. If you ever find an if statement inside one, it belongs in the controller instead.

src/routes/reportRoute.js
javascript
import { Router } from 'express';
import {
  getAllReports,
  getReportById,
  createReport
} from '../controllers/reportController.js';

const router = Router();

// Paths here are RELATIVE to wherever this router is mounted
router.get('/', getAllReports);
router.get('/:id', getReportById);
router.post('/', createReport);

export default router;
⚠️

Pass the function reference, not a call: write router.get('/', getAllReports). Writing getAllReports() with brackets runs the function immediately at startup and registers undefined as the handler.

With the router in place, index.js no longer answers a single report request itself. It creates the app, registers app-wide middleware, mounts the router, and listens.

The two block handlers stay exactly where they are for now, so your file should look like this:

index.js
javascript
import express from 'express';
import reportRoute from './src/routes/reportRoute.js';

const app = express();
app.use(express.json());

// Every path inside reportRoute is prefixed with /api/reports
app.use('/api/reports', reportRoute);

// --- Block endpoints: LEAVE THESE HERE, you move them in Section 6 ---
app.get('/api/blocks', (req, res) => {
  ...
});

app.get('/api/blocks/:id', (req, res) => {
  ...
});

app.listen(3000, () => {
  console.log('Mosquito server running on port 3000');
});
💡

Paths inside the router are relative to the mount point. Because the router is mounted at /api/reports, router.get('/') answers /api/reports and router.get('/:id') answers /api/reports/:id. If you write the full path inside the router by mistake, the real URL becomes /api/reports/api/reports.

07
src/utils: Stop Repeating Yourself
The same find-by-id line now sits in two files: getReportById in reportController.js and getBlockById in blockController.js. Duplication like that is the signal to extract a utility.

Here is the duplicated line, once in each controller:

• reportController.js → reports.find((r) => r.id === Number(req.params.id))
• blockController.js → blocks.find((b) => b.id === Number(req.params.id))

Only the array and the variable name differ, which means the logic can be written once and handed both. That extracted version is a utility: a pure function that takes arguments, returns a value, and knows nothing about req, res, or Express. Knowing nothing about Express is exactly what makes it reusable across controllers and easy to test on its own.

You will create two utility files in this section, one for generic array work and one for mosquito risk scoring.

The first utils file is src/utils/collectionUtils.js, for helpers that work on any array of records:

src/utils/collectionUtils.js
javascript
/**
 * Finds an item by numeric id in any array of objects that has an `id`.
 * Works for blocks, reports, inspectors, anything.
 */
const findById = (collection, id) =>
  collection.find((item) => item.id === Number(id));

/**
 * Returns the next id for an in-memory collection.
 * Safer than collection.length + 1, which repeats an id if a record is ever removed.
 */
const getNextId = (collection) => {
  let highestId = 0;

  for (const item of collection) {
    if (item.id > highestId) {
      highestId = item.id;
    }
  }

  return highestId + 1;
};

export { findById, getNextId };

The second is src/utils/riskUtils.js, which holds logic specific to mosquito detection: turning a raw larvae count into a risk level that NEA officers act on.

src/utils/riskUtils.js
javascript
/**
 * Maps a larvae count to an HDB mosquito risk level.
 *   >= 10 -> high    (fogging required)
 *   >= 5  -> medium  (follow-up inspection)
 *   else  -> low
 */
const getRiskLevel = (larvaeCount) => {
  if (larvaeCount >= 10) return 'high';
  if (larvaeCount >= 5) return 'medium';
  return 'low';
};

/**
 * Adds a computed riskLevel field without mutating the original report.
 */
const withRiskLevel = (report) => ({
  ...report,
  riskLevel: getRiskLevel(report.larvaeCount)
});

export { getRiskLevel, withRiskLevel };

With both utils files in place, src/controllers/reportController.js gets shorter and reads like a description of the endpoint instead of a pile of array plumbing.

08
src/middleware: Reusable Logic That Runs Before Your Handlers
The final layer. Write a rule once, then apply it to as many routes as you like.

A middleware function has the signature (req, res, next). It can inspect or change the request, then either call next() to pass control to the next function in the chain, or end the request itself with a response.

Those are the only two endings. If a middleware does neither, the request hangs forever with no error and no response.

Start with a logger, in src/middleware/requestLogger.js:

src/middleware/requestLogger.js
javascript
// Runs for EVERY request in the app
const requestLogger = (req, res, next) => {
  const timestamp = new Date().toISOString();
  console.log(`[${timestamp}] ${req.method} ${req.originalUrl}`);
  next(); // without this, the request never reaches the controller
};

export { requestLogger };

Next comes the validation you removed from createReport earlier, in src/middleware/validateReport.js.

Written as middleware, the same function can guard the POST and the PUT endpoints, and that is the reusability payoff:

src/middleware/validateReport.js
javascript
import { blocks } from '../data/store.js';
import { findById } from '../utils/collectionUtils.js';

const validateReport = (req, res, next) => {
  const { blockId, larvaeCount } = req.body;

  if (blockId === undefined || larvaeCount === undefined) {
    return res.status(400).json({
      message: 'blockId and larvaeCount are required'
    });
  }

  if (typeof larvaeCount !== 'number' || larvaeCount < 0) {
    return res.status(400).json({
      message: 'larvaeCount must be a number that is 0 or greater'
    });
  }

  if (!findById(blocks, blockId)) {
    return res.status(404).json({
      message: `No HDB block found with id ${blockId}`
    });
  }

  next(); // all checks passed, hand over to the controller
};

export { validateReport };

Middleware is registered at different levels. App level runs on every request, so that is where the logger goes:

index.js
javascript
import express from 'express';
import reportRoute from './src/routes/reportRoute.js';
import blockRoute from './src/routes/blockRoute.js';
import { requestLogger } from './src/middleware/requestLogger.js';

const app = express();

app.use(express.json());
app.use(requestLogger); // APP level: runs on every request

app.use('/api/reports', reportRoute);
app.use('/api/blocks', blockRoute);

app.listen(3000, () => {
  console.log('Mosquito server running on port 3000');
});

Route level runs only for one endpoint, so that is where the validator goes:

src/routes/reportRoute.js
javascript
import { Router } from 'express';
import {
  getAllReports,
  getReportById,
  createReport
} from '../controllers/reportController.js';
import { validateReport } from '../middleware/validateReport.js';

const router = Router();

router.get('/', getAllReports);
router.get('/:id', getReportById);

// ROUTE level: validateReport runs first, createReport only if next() was called
router.post('/', validateReport, createReport);

export default router;
💡

Order matters. app.use(express.json()) must come before anything that reads req.body, and requestLogger must be registered before the route mounts or it will never fire for them.
