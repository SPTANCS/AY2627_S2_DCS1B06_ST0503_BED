Start from the provided starter folder and finish with a working "npm run db command" that creates database tables and fills them with starter data.

📖 Concept
Step 1 of 8
01
What Is Database Seeding?
Why we fill a fresh database with starter data.

Seeding means loading a database with an initial set of data. When you clone a project or wipe your local database, the tables start empty. A seed script recreates the tables and inserts known sample rows so you always have something to build against.

In this lesson you start from the provided db-seeding-starter folder and build the database layer yourself. You will initialise the project, install packages, describe your tables, and write the command npm run db. When that command runs it does two things: it makes sure the tables described in your schema exist, then it inserts sample data into any table that is still empty.

  schema.js            seed.js               local.db
 +-------------+       +-------------+       +-------------+
 | table       | ----> | push tables | ----> |  authors    |
 | data type   |       | + insert    |       |  animes     |
 +-------------+       |   sample    |       | (with rows) |
                       |   rows      |       +-------------+
                       +-------------+

schema.js defines column & type, seed.js generates the database file (local.db)

💡

A good seed script is idempotent: running it many times does not create duplicate data. We achieve this by only inserting into a table when it is empty.

Step 3 of 8
03
Create the Connection, Config, and Schema
The three files the seed relies on.

Do this: create the three files below in your code editor. The connection and config are infrastructure you write once and leave alone. The schema is where you describe your tables, so you will come back to it whenever you add a new one. First you need a src/db folder. You can make it in your editor, or run the command below in your terminal from the root folder:

bash
mkdir -p src/db

File 1: connection.js. This file opens the SQLite database and exports a db object that every query goes through. In your editor, create src/db/connection.js with the code below.

src/db/connection.js
javascript
import { createClient } from '@libsql/client';
import { drizzle } from 'drizzle-orm/libsql';

const client = createClient({
  url: 'file:local.db',
});

export const db = drizzle(client);

Here is what each line does: 

import { createClient } from '@libsql/client' brings in the low-level SQLite client.

import { drizzle } from 'drizzle-orm/libsql' brings in the Drizzle ORM wrapper.

createClient({ url: 'file:local.db' }) opens the database stored in the file local.db, creating that file if it does not exist yet.

 drizzle(client) wraps the client so you can query with JavaScript instead of raw SQL.

export const db shares that wrapped connection, so every other file imports the same db.

Notice the drizzle wrapper around the client... because:

Drizzle is an ORM (Object Relational Mapper), an extra layer that sits between your code and the database. Later you will query the database with ORM code written in JavaScript, but databases only understand SQL. The ORM translates your JavaScript into the SQL the database runs for you.

Drizzle (JavaScript, what you write) SQL (what the database actually runs)
db.select().from(authors) SELECT * FROM authors;

File 2: drizzle.config.js. This file tells the Drizzle CLI where your schema lives and which database file to push tables into. In your editor, create drizzle.config.js in the project root, next to package.json.

drizzle.config.js
javascript
export default {
  schema: './src/db/schema.js',
  dialect: 'sqlite',
  dbCredentials: {
    url: 'file:local.db',
  },
};

Each field tells the Drizzle CLI how to build your database:

schema points at the file that defines your tables, so the CLI knows what to create.

dialect: 'sqlite' says which database engine you are using.

 dbCredentials.url points at the same local.db file as your connection, so the CLI and your app read and write one shared database.

File 3: schema.js. This file describes your tables in JavaScript. In your editor, create src/db/schema.js with two tables: authors, and animes which references an author by id. That reference makes a one-to-many relationship, where one author can have many animes.

src/db/schema.js
javascript
import { sqliteTable, text, integer } from 'drizzle-orm/sqlite-core';

// An author can have many animes.
export const authors = sqliteTable('authors', {
  id: integer('id').primaryKey({ autoIncrement: true }),
  name: text('name').notNull(),
  bio: text('bio'),
});

// Each anime belongs to one author (authorId points at authors.id).
export const animes = sqliteTable('animes', {
  id: integer('id').primaryKey({ autoIncrement: true }),
  title: text('title').notNull(),
  genre: text('genre'),
  episodes: integer('episodes'),
  authorId: integer('author_id').references(() => authors.id),
});

Walking through the authors table:

import { sqliteTable, text, integer } brings in the helpers for defining a table and its column types.

sqliteTable('authors', { ... }) defines a table named authors, and the object describes its columns.

integer('id').primaryKey({ autoIncrement: true }) makes id the primary key that counts up automatically for each new row.

text('name').notNull() is a required text column, so every author must have a name.

text('bio') is an optional text column, so it can be left empty.

The animes table follows the same pattern, with one extra column that creates the relationship: authorId: integer('author_id').references(() => authors.id) stores an author's id on each anime. That reference is what links every anime back to one row in authors, giving you the one-to-many relationship.

Correct!
Right. schema.js defines table structure; the connection and seeding happen elsewhere.

04
Write seed.js Step by Step
Build the script that npm run db will execute.

Do this: in your code editor, open src/db/seed.js from the starter and build up the seeding logic using the steps below. Add each block in order. By the end the whole file is complete.

1
Import the tools: execSync to run the table-creation command, plus db and your tables.
2
Define the sample data arrays you want to insert.
3
Run npx drizzle-kit push to create the tables from the schema.
4
For each table, check if it is empty and only insert when it is.
5
Resolve the relationship so each anime points at the correct author id.

Step 1: Imports. Add these lines at the top of seed.js, above the sample data. execSync lets Node run a shell command and wait for it to finish. You also import the db object and the two table definitions.

src/db/seed.js
javascript
import { execSync } from 'child_process';

import { db } from './connection.js';
import { authors, animes } from './schema.js';

Step 2: Sample data. The sample data already lives in your starter's seed.js, so you do not need to type it. It looks like the arrays below, shown abbreviated here. Authors are plain rows. For animes we store the author's name rather than the id for now, because the real id is only known after the authors are inserted.

src/db/seed.js
javascript
// already provided in the starter
const sampleAuthors = [
  { name: 'Eiichiro Oda', bio: 'Creator of One Piece.' },
  { name: 'Hajime Isayama', bio: 'Creator of Attack on Titan.' },
  { name: 'Akira Toriyama', bio: 'Creator of Dragon Ball and Dr. Slump.' },
];

// `author` is the author name; it gets swapped for the real authorId before inserting.
const sampleAnimes = [
  { title: 'One Piece', genre: 'Adventure', episodes: 1000, author: 'Eiichiro Oda' },
  { title: 'Attack on Titan', genre: 'Action', episodes: 25, author: 'Hajime Isayama' },
  { title: 'Dragon Ball Z', genre: 'Action', episodes: 291, author: 'Akira Toriyama' },
  { title: 'Dr. Slump', genre: 'Comedy', episodes: 243, author: 'Akira Toriyama' },
];

Step 3: Create the tables. The seed pushes your schema into the database before inserting anything. Add the line below. It only creates what does not already exist, so it is safe to run every time.

src/db/seed.js
javascript
console.log('Creating tables from schema...');
execSync('npx drizzle-kit push', { stdio: 'inherit' });
💡

The option { stdio: 'inherit' } forwards the command's output straight to your terminal so you can see the push progress live.

Step 4: Seed authors when empty. Insert the sample authors only if the table has no rows yet. Add this block. It reads the table first, inserts the authors when the table is empty, and skips otherwise so you never duplicate data.

src/db/seed.js
javascript
const existingAuthors = await db.select().from(authors);

if (existingAuthors.length === 0) {
  await db.insert(authors).values(sampleAuthors);
  console.log(`Inserted ${sampleAuthors.length} authors`);
} else {
  console.log('Authors already seeded, skipping.');
}

Step 5: Seed animes and wire up the relationship. Each anime needs the real id of its author, which only exists after the authors are inserted. Add this final block. It reads the inserted authors back, then maps every sample anime to its author's id before inserting.

src/db/seed.js
javascript
const existingAnimes = await db.select().from(animes);

if (existingAnimes.length === 0) {
  const allAuthors = await db.select().from(authors);

  const animeRows = sampleAnimes.map((anime) => {
    const author = allAuthors.find((a) => a.name === anime.author);
    return {
      title: anime.title,
      genre: anime.genre,
      episodes: anime.episodes,
      authorId: author.id,
    };
  });

  await db.insert(animes).values(animeRows);
  console.log(`Inserted ${animeRows.length} animes`);
} else {
  console.log('Animes already seeded, skipping.');
}

console.log('Done! Database is ready.');
⚠️

Order matters. You must insert authors before animes, because each anime's authorId must reference an author that already exists. Seeding animes first would leave you with no valid id to point at.

Step 5 of 8
05
Run npm run db
Execute your seed and confirm the database is built.

Do this: you already added the "db" script to package.json during setup. In your terminal, from the project root, run:

bash
npm run db

The first run creates local.db, pushes the tables, and inserts the sample rows

 You should see log lines about creating tables and inserting authors and animes, ending with Done! Database is ready.

Now run it again. In your terminal, run npm run db a second time. It recreates any missing tables but skips seeding, printing the 'already seeded' messages. That is proof your script is idempotent, meaning repeated runs do not change the result.

The seed file is a plain Node script that uses import syntax. Because package.json sets "type": "module", Node runs it as an ES module, so top-level await and imports work directly.
Edit the table in schema.js, then run npm run db again. The push step reshapes the tables to match. If you want fresh seed data, delete local.db first so the tables come back empty and get reseeded.

Using This in CA1 and CA2
You will not build the database layer from scratch again.

You built everything from scratch here so the whole flow makes sense. For CA1 and CA2 you do not have to repeat that. Your starter code already includes a sample src/db folder, with the connection, schema, and seed set up for you.

Your job is to edit that sample src/db for your own project's requirements. In your editor, swap the sample tables in schema.js for the ones your project needs and replace the sample data in seed.js. Then run npm run db in your terminal to build and seed your database.
